# 데이터 모델

모든 데이터는 `npm run gen:data`가 고정 시드로 만든 가상 데이터다. 계층은 ISA-95의 장비 계층(기업 → 사업장 → 영역 → 라인 → 설비)을 참고했다.

## 1. 계층과 키

```
회사 HGM
└─ 사업장 ASN · GMH · DGU · HWS
   └─ 라인 ASN-PR1 …            (공정 유형: press, welding, injection, painting, machining, assembly)
      └─ 설비 ASN-PR1-M01 …      (감시 대상 여부, 수집 장치)
         └─ 센서 ASN-PR1-M01-VIB …
제품(품번) HG-FSM-210 … ── 고객사 CUS-A·B·C
금형 MLD-GMH-410-01 …  ── 설비에 장착 이력
자재 로트 MAT-… ── 생산 로트에 투입
```

- 키는 사업장 코드로 시작한다. 실제 설비 번호 체계를 흉내 내지 않는다.
- 생산 로트 키: `LOT-<라인>-<YYMMDD>-<교대>-<순번>` 예: `LOT-GMH-IM1-260924-B-02`

## 2. 데이터 묶음

| 묶음 | 내용 | 단위·기간 | 파일 |
| --- | --- | --- | --- |
| 기준정보 | 사업장, 라인, 설비, 센서, 금형, 제품, 고객사, 교대, 사용자, 역할, 수집 장치 | — | `master/*.json` |
| 단가·기준선 | 가상 단가, 기준선 기간, 투자비, 변경 이력 | 적용 시작일별 | `master/unit-costs.json`, `master/ax-settings.json` |
| 생산 실적 | 라인 × 교대 × 제품: 계획 수량, 총생산, 양품, 불량(유형별), 재작업, 가동 시간 | 교대, 1년 | `production/<사업장>.json` |
| 생산 로트 | 로트별 수량, 설비, 금형, 자재 로트, 공정 조건 요약(평균·최소·최대), 검사 결과, 출하처 | 로트(교대당 1~3개), 1년 | `lots/<사업장>-<분기>.json` |
| 비가동 사건 | 설비, 시작·종료, 손실 분류, 원인 코드, 메모 | 사건, 1년 | `events/downtime-<사업장>.json` |
| 설비 센서 특징값 | 감시 설비별 진동 RMS, 베어링·모터 온도, 전류(시간 평균) | 1시간, 6개월 | `sensors/hourly-<사업장>.json` |
| 설비 센서 상세 | 시나리오 설비의 1분 값 | 1분, 최근 24시간 | `sensors/minute-<설비>.json` |
| 정비 오더 | 유형(예방·사후·예지), 단계, 요청·승인·작업·완료 시각, 작업 시간, 부품비, 연결된 AI 결과 | 건, 1년 | `maintenance/work-orders.json` |
| 품질 클레임 | 고객사, 품번, 접수일, 불량 유형, 수량, 단계, 연결 로트 | 건, 1년 | `quality/claims.json` |
| 에너지 | 라인·유틸리티 × 에너지원(전력, 압축공기, LNG) | 1시간 1년, 15분 최근 7일 | `energy/hourly-<사업장>.json`, `energy/quarter-<사업장>.json` |
| 알림 | 규칙·AI·시스템 알림 | 건, 최근 60일 | `events/alerts.json` |
| AI 결과 기록 | 과거 AI 결과와 판정(채택·기각, 사유) | 건, 6개월 | `ai/results.json` |
| 수집 상태 | 수집 장치별 마지막 수신 시각, 미수신 구간 | 현재 | `events/collection.json` |

AI 엔진의 현재 결과(건전성, 잔여수명, 원인 후보)는 저장하지 않고 화면이 열릴 때 데이터에서 계산한다. 과거 결과와 판정만 기록으로 둔다.

설비 가동 화면(OPS-060)의 공정도는 데이터가 아니라 화면 구성이라 `config/hmi/HMI-<사업장>-<번호>.json`에 둔다(사업장마다 시연 화면 1개, 게시 v1). 객체는 설비 심볼(설비·신호 연결), 선(컨베이어·배관), 영역(라인 연결), 글자 네 종류이고 좌표는 1600 × 900 논리 캔버스 기준이다. 화면 디자이너(SET-080)의 편집본과 이후 게시본은 브라우저 저장소 덧씌우기(`ax-prototype.hmi-screens`, D-04)다(D-71).

## 3. 규모와 용량 목표

| 항목 | 대략 |

| 라인 11개, 설비 154대(감시 56대), 센서 168개(감시 설비 × 진동·온도·전류), 금형 38개, 제품 10개 | |

| 비가동 사건: 고장·교체(5분 이상). 소정지는 교대 실적의 건수·합계로 둔다 | 약 1만 건 |
| 센서 특징값: 56대 × 3신호 × 4,382시간 | 약 74만 값 |
| 에너지: 11라인 + 유틸리티 4 × 평균 2.3원 × 8,760시간 | 약 30만 값 |

- `public/mock` 전체 30MB 이하, 파일 150개 이하로 한다. 3단계 결과: 55개, 17.0 MB. 게시 한도(한 버전 511개 파일)에서 글꼴 파일 몫을 빼야 하기 때문이다(D-11).
- 시계열은 v1처럼 정수 배열 + 배율로 저장한다. 공정 조건 요약값은 `digits`에 맞춰 반올림한다.
- 사업장·기간으로 파일을 나눠 화면이 필요한 것만 읽는다.

## 3-1. 라인 구조

- 사출·가공 라인은 설비가 나란히 일한다(parallel). 설비 1대의 정지는 라인 시간으로 1/설비 수만큼 손실이다. 교대 실적의 손실 분은 라인 기준 분이다.
- 프레스·용접·도장·조립 라인은 직렬이다. 설비 정지가 곧 라인 정지다.
- 라인마다 투입 인원(crew)과 납기 제약 여부(constrained)를 둔다(D-18).
- 제품의 마지막 라인 로트만 출하한다. 앞 라인 로트는 다음 라인으로 넘어간다.

## 4. 일관성 규칙(테스트로 검사)

1. 라인 합 = 사업장 합 = 전사 합(수량, 시간, 에너지, 금액)
2. 양품 + 불량 = 총생산, 재작업 ⊂ 불량
3. 계획 가동 시간 − 6대 손실 합 = 완전 가동 시간(오차는 반올림 1초 이내)
4. 교대 실적의 정지 손실 시간 = 같은 교대 비가동 사건 시간의 합
5. 로트 수량 합 = 교대 실적 총생산
6. 클레임 → 로트 → 설비·금형·자재 로트·공정 조건 연결이 끊기지 않는다
7. 정비 오더의 완료 시각 이후에 같은 고장 모드 신호가 정상 범위로 돌아온다(예지 정비 사례)
8. 비생산 시간 에너지 사용량은 교대 일정 밖 시간의 합과 같다

## 6. 원본 시스템과 과업 범위 (D-63)

제조 AX는 업무 기록 시스템이 아니라 기존 시스템의 데이터를 읽어 분석·판단하는 층이다. 각 데이터의 원본은 아래 시스템이고, AX는 연계해 조회한다. 원본 시스템이 없는 고객은 정해진 엑셀 양식으로 작성해 업로드한다(SET-070에서 업로드 이력 관리). 측정 장비 직접 연계와 수기 입력 화면은 범위 밖이다.

| 데이터 | 원본 시스템 | 시스템이 없을 때 | AX가 직접 갖는 것 | 화면 |
| --- | --- | --- | --- | --- |
| 생산 실적·로트·출하 | MES | 엑셀 양식(교대 실적, 로트) | — | OPS·QUA |
| 설비 가동·정지 사건 | MES·설비 수집 장치 | 엑셀 양식(정지 사건) | 수집 상태(미수신) | OPS-030, OPS-050 |
| 설비 센서 | 수집 장치·PLC | 없음(예지 진단 불가로 표시) | AI 진단·판정 | MNT-010·011 |
| 검사 결과·품질 비용 | QMS, 검사 장비가 이미 모은 결과 | 엑셀 양식(검사 실적) | 원인 후보·권장 조건과 판정 | QUA-010·040(연계 조회, 다음 버전), QUA-020 |
| 고객 클레임 | QMS 또는 영업 시스템(CRM) | 엑셀 양식(클레임 목록) | 로트 역추적 결과 | QUA-030 |
| 정비 오더·이력·예방 정비 계획 | CMMS·EAM | 엑셀 양식(정비 오더, 예방 정비 계획) | AI 결과와 오더의 연결 | MNT-010 진행 중인 정비, MNT-011 정비 이력(연계 조회). 정비 요청·처리·이력·계획 메뉴는 두지 않음(D-66) |
| 에너지 계량 | EMS·계량기 | 엑셀 양식(일·시간 사용량) | 낭비 탐지 | ENG-010·020 |
| 단가·원가 | ERP | SET-020 입력 | 적용 시작일과 변경 이력 | SET-020 |
| AX 투자비·운영비 | ERP 예산(예산 관리는 범위 밖) | SET-020 입력 | ROI 계산에 쓰는 몇 개 항목 | EXE-020 |

QUA-030(클레임·로트 추적)의 처리 단계는 유지하고 확장성(원본 시스템 연계 또는 엑셀 업로드 후 이 화면에서 처리)으로 소개한다. 정비 요청·처리는 설비관리 시스템의 업무라 두지 않는다(D-66).
