# 가상 AI 엔진 규격

AI 결과는 화면에 보여 주되 계산은 가상 엔진이 한다. `src/data/aiEngine.ts`에 어댑터 인터페이스와 mock 구현을 둔다. 실제 모델이나 외부 API를 부르지 않는다. 나중에 실제 엔진을 붙일 때는 이 인터페이스 아래 구현만 바꾼다.

## 1. 원칙

- **결정적**: 같은 입력이면 항상 같은 결과다. 난수를 쓰지 않고 데이터에서 계산한다.
- **근거 우선**: 결과마다 근거 신호·변수와 정상 범위, 차이를 함께 돌려준다. 근거를 만들 수 없으면 결과를 내지 않는다.
- **신뢰도는 숫자로**: 0~1 값과 높음·보통·낮음 등급(terms.json). 신뢰도는 상태 등급과 섞지 않는다.
- **판정은 사람이**: 결과에 채택·기각을 기록한다. 기각은 사유가 필수다. 판정은 결과를 지우지 않는다.
- **표시**: 모든 결과에 모델 이름, 버전, 생성 시각, "가상 엔진" 표시

## 2. 공통 형식

```ts
interface AiResult<T> {
  id: string;                 // AIR-<yyyymmdd>-<seq>, 같은 입력이면 같은 id
  kind: 'anomaly' | 'health' | 'rul' | 'rootCause' | 'recommendation' | 'answer';
  target: { siteId: string; lineId?: string; equipmentId?: string; productId?: string; lotIds?: string[] };
  generatedAt: string;        // company.json now 기준
  model: { name: string; version: string; trainedFrom: string; trainedTo: string };
  level?: '긴급' | '주의' | '참고';   // 알림이 필요한 결과만
  confidence: number;         // 0~1
  conclusion: string;         // 한 문장
  evidence: Evidence[];       // 상위 3개 이상
  impact?: { downtimeHours?: [number, number]; defectQty?: number; costKrw?: [number, number] };
  payload: T;
  decision?: { value: '채택' | '기각'; reason?: string; by: string; at: string };
}
interface Evidence { label: string; value: number; normalRange: [number, number]; unit: string; delta: number; chartRef?: string }
```

## 3. 기능

### 3.1 이상 탐지와 건전성 지수 — `health(equipmentId)`

- 입력: 감시 설비의 시간별 센서 특징값(최근 30일), 같은 설비의 정상 기간(기준 14일)
- 계산(mock): 신호마다 정상 기간 평균·표준편차로 z 점수를 만들고, 가중 합을 0~100 지수로 바꾼다. 100 = 정상 기간과 같음. 지수 < 70이면 주의, < 50이면 긴급 알림
- 출력: 지수, 최근 30일 추이, 기여 신호 상위 3개, 추정 고장 모드(진동·온도 조합 규칙: 베어링, 정렬 불량, 과부하, 냉각 불량)

### 3.2 잔여수명 — `rul(equipmentId)`

- 계산(mock): 지수의 최근 14일 추세를 선형으로 늘려 임계(40)에 닿는 시점. 추세 기울기의 신뢰 구간으로 하한·상한(p10·p90)을 만든다.
- 출력: 중앙값과 구간(일), 임계 값, 적합 기간. 추세가 없거나 지수가 오르면 "예측 불가 · 추세 없음"
- 표시: 구간을 먼저 보여 준다(예: 7~15일, 중앙값 10일).

### 3.3 불량 원인 후보 — `rootCause({ productId, defectType, from, to, lineId? })`

- 입력: 대상 기간의 로트(공정 조건 요약, 설비, 금형, 자재 로트, 교대, 불량 수량)
- 비교 집단: 불량률이 기간 중앙값의 1.6배 이상(최소 0.5%)인 로트 대 나머지. 집단 크기를 함께 돌려준다.
- 계산(mock):
  - 연속 변수: 두 집단의 평균 차이를 정상 집단 표준편차로 나눈 효과 크기. 분모에는 정상 평균의 5% 하한을 둔다(관리 폭이 아주 좁은 변수가 순위를 독점하지 않게).`n  - 연속 변수 중 공정 조건의 변동(최대−최소)도 따로 후보로 본다(예: 금형 온도 편차).
  - 범주 변수(설비, 금형, 자재 로트, 교대): 범주별 불량 로트 비율의 차이
  - 효과 크기 순으로 정렬하고, 표본 수와 효과 크기로 신뢰도를 정한다.
- 출력: 후보 목록(변수, 방향, 효과 크기, 불량 집단 범위, 정상 집단 범위, 표본 수, 신뢰도), 상위 후보의 산점도 데이터
- 주의 문구: "상관에 근거한 후보이며 인과는 현장 확인이 필요합니다."

### 3.4 권장 조건 — `recommend({ productId, lineId })`

- 계산(mock): 원인 후보 상위 2개 변수에 대해, 불량률이 낮은 로트 상위 25%의 범위를 권장 범위로 낸다.
- 출력: 변수별 권장 범위, 그 범위에서의 과거 불량률, 예상 불량 감소 수량과 금액(roi 단가 사용), 신뢰도
- 채택하면 잠재 효과(`fx.potential.*`)에 들어가고, 이후 데이터가 개선되면 확정 항목의 근거에 채택 이력이 표시된다.

### 3.5 에너지 낭비 탐지 — `energyWaste(siteId)`

- 비생산 시간(교대 일정 밖) 기저 사용량을 기준 기간과 비교해 증가분과 금액을 낸다(SC-04).

### 3.6 자연어 질의 — `answer(question, context)`

- 실제 언어 모델을 쓰지 않는다. 질문을 지원 의도 목록과 맞춰 의도와 조건(사업장, 라인, 기간, 지표)을 뽑는다.
- 지원 의도(초안): 지표 값 조회, 가장 낮은·높은 대상, 변화 원인, 정비가 필요한 설비, AX 효과, 클레임 관련 로트
- 답은 지표 계산 함수와 위 기능의 결과로 만든다. 수치·기간·사업장과 관련 화면 링크를 함께 준다.
- 맞는 의도가 없으면 지원 범위를 안내한다. 답을 만들어 내지 않는다.
- 같은 질문(정규화한 문자열)에는 항상 같은 답을 준다.

## 4. 판정과 이력

- 채택·기각은 브라우저 저장소 덧씌우기(v1 D-04 방식)로 저장하고 `ai/results.json` 원본 위에 합쳐 AIX-020에 보인다.
- 채택한 정비 제안은 MNT-020 '요청'으로, 채택한 권장 조건은 품질 조치 기록으로 이어진다.
- 엔진 버전을 바꾸면 결과 id가 바뀐다. 과거 판정은 그 버전의 결과에 남는다.

## 5. 규격 확정 전 항목

실제 엔진과의 연계 규격(전송 방식, 주기, 인증)은 정하지 않았다. 화면의 관련 입력 항목에는 "규격 확정 전"을 표시한다.
