## 확인한 것

- 1920×1080 DOM 점검(패널·카드·차트·그리드 겹침, 글자 잘림, 가로 넘침): OPS-020(전사, 대구 라인, 설비 계층), MNT-010, MNT-011(아산 메인 프레스, 김해 건조로 2호), MNT-020(목록·처리·신규), QUA-020(로트 선택 포함), QUA-030, OPS-010(아산, 대구), OPS-050, ENG-010(화성), EXE-010, EXE-020 — 최종 상태에서 겹침 0, 잘림 0, 가로 넘침 없음. 처음 점검에서 나온 잘림(설비 이름, 정비 이력 내용, 로트 표, 에너지 표 머리글, 비가동 이력 라인 이름)은 고쳤다.
- 어둡게: OPS-020, QUA-020 화면 캡처로 확인.
- 콘솔: 콘솔을 비운 뒤 OPS-020·MNT-010·MNT-011·MNT-020·QUA-020·QUA-030·OPS-010·OPS-050·ENG-010·EXE-020을 차례로 열어 오류 0건. 산점도가 있는 QUA-020을 떠날 때 ECharts "disposed" 경고 2건이 나와 정리 순서를 고쳤고, 다시 확인해 경고 0건.
- 권한: 대표이사(조회)로 MNT-020을 열면 "조회 권한으로 열었습니다"와 처리 버튼 없음, 공장장·설비 엔지니어(편집)는 처리 버튼이 보임. 권한 밖 사업장 설비로 신규 요청을 열면 안내.
- `npm run check`: check:tokens, check:screens(화면 정의 12개), check:licenses, 테스트 35개(6단계 5개 추가), 빌드 모두 통과.
- 시험으로 처리한 정비·클레임·알림 변경은 브라우저 저장소에서 지웠다.

- OPS-020 설비 표의 고장·교체 시간이 비어 보임(행에 값 필드 없음) → 행에 값을 넣음

## 확인하지 못한 것

- 다시 만든 PDF 견본을 열어 눈으로 보지 못했다(이 환경의 PDF 미리보기가 캡처를 지원하지 않음). 보고서 모델과 화면 값의 일치는 기존 테스트로 확인했다.
- 1920×1080 화면 캡처는 이번에도 축소되어 찍혔다. 배치는 DOM 치수로 확인했다.

- 클레임 "반려"와 정비 "반려" 경로는 화면에서 눌러 보지 않았다.

## 남은 문제(고치지 않음)

- 가상 데이터에서 일부 정비 오더 제목이 설비 종류와 맞지 않는다(예: "건조로 2호 도장 로봇 이상 수리"). 고장 사건의 원인을 라인 단위로 고른 뒤 설비를 붙인 생성 방식 때문이다. 수치에는 영향이 없고, 고치려면 `gen:data`를 다시 돌려야 해서 이번 단계에서는 두었다.
- 고정 현재 시각 때문에 화면에서 처리한 단계가 모두 같은 시각(2026-09-30 14:30)으로 기록된다(D-54).
- 빌드 결과 주 JS가 3.3MB(압축 1.0MB)다. 시연에는 문제없으나 8단계 게시 전에 화면별 나눠 싣기를 검토할 수 있다.
