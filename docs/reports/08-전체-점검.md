# 8단계 보고 — 시연 흐름 확정과 전체 점검

> 추가(보고 후 요청으로 수정): 높음 2건을 고쳤다. H1 — COM-020 알림 상세를 P7(`config/screens/COM-020.json`, `src/patterns/P7/P7Alert.tsx`)로 만들었다. H2 — MNT-020·QUA-030 내용 패널이 선택한 사업장 밖의 기록을 열지 않고 MNT-011과 같은 안내를 보인다. 결정은 D-61~D-62. 아래 본문은 점검 당시 그대로 둔다.

지시서대로 이번 단계는 점검만 했다. 아래 문제는 고치지 않았고, 수정은 이 보고를 본 뒤 따로 요청받아 한다. 단, 7단계에서 내가 넣은 표 숫자 열 오른쪽 정렬이 만든 회귀(스크롤바를 겹쳐 그리는 환경에서 마지막 숫자 열이 가림)는 점검 중 발견해 7단계 수정으로 고쳤다(커밋 "Keep right-aligned last grid column clear of overlay scrollbars").

점검 방법: 개발 서버를 Chromium(Playwright)으로 열어 1920×1080에서 패널·카드 겹침, 글자·표 잘림, 가로 넘침, 콘솔 오류·경고, 실패한 요청을 DOM으로 재고 화면 캡처를 눈으로 봤다. 화면마다 새 브라우저 저장소로 열었다. 사용자 전환은 로그인 화면(COM-040)에서 했다.

## 8. 확인하지 못한 것

- Artifact로 게시한 상태(실제 호스트에서의 경로, `downloads` 저장 확인 창)는 게시 전이라 확인하지 못했다.
- 내려받은 PDF 파일 이름: 브라우저 자동화가 이름을 "download"로 보고했다. 코드에는 `경영보고서_2026-09_전사.pdf`로 정해져 있어 자동화 쪽 표시로 보이지만, 실제 브라우저에서 확인하지 못했다. PDF 내용은 텍스트로 뽑아 화면 값과 대조했다.
- PDF를 눈으로 보지 못했다(이 환경의 PDF 미리보기 제약). 텍스트 대조만 했다.
- 클레임 처리(원인 기록 → 대책 → 종결)와 반려 경로, 알림 센터 드로어에서의 확인·조치 처리는 이번에 눌러 보지 않았다(6단계에서 확인).
- 다음 버전 화면 16개 중 EXE-040만 열었다.
- 실제 macOS·Windows 브라우저와 화면 배율(125% 등)은 확인하지 못했다. 스크롤바를 겹쳐 그리는 환경은 Chromium 옵션으로 흉내 내 확인했다.
