# 2단계 — 프로젝트 뼈대와 공통 틀

승인된 설계 문서를 기준으로 프로젝트를 만든다. v1(`D:\ems-prototype`)에서 재사용할 수 있는 것은 복사해서 고친다(토큰 체계, 공통 틀, 패턴 템플릿 구조, 검사 스크립트, 게시용 빌드). v1 파일은 수정하지 않는다.

## 할 일

1. Vite + React + TypeScript 프로젝트를 이 폴더에 만든다. 해시 라우팅과 상대 경로(`base: './'`)를 처음부터 쓴다.
2. 패키지를 설치하고 라이선스를 확인한다. `npm run check:licenses`가 통과해야 한다.
3. 디자인 토큰
   - `docs/tokens.css`를 원본으로 하고 `npm run tokens:sync`로 `src/styles/tokens.css`를 만든다.
   - 밝은·어두운 테마, 조밀·표준 밀도. 경영진 화면용으로 글자가 큰 "발표" 밀도를 검토한다(설계 문서에 정한 경우).
   - 상태색 4단계, 금액·효과 표시용 토큰(확정·추정·잠재), AI 결과 표시용 토큰
   - Ant Design 테마, ECharts 테마, AG Grid 테마가 같은 토큰을 읽는다.
4. 공통 틀: 상단 바(회사, 사업장 선택, "가상 데이터"·"시연용" 표시, 알림, 사용자, AI 도우미 열기), 역할별 메뉴, 제목 줄, 조건, 툴바, 본문. 사용자 역할이 바뀌면 메뉴와 첫 화면이 바뀐다.
5. 화면 정의: `config/screens/<화면ID>.json` 형식과 JSON 스키마를 정하고, 설계 문서의 패턴별 템플릿 뼈대를 만든다. 다음 버전 화면은 메뉴에서 열면 "준비 중" 안내를 보인다.
6. 검사 스크립트: check:tokens, check:screens(메뉴·정의·용어·지표 이름 일치), check:licenses, test, 그리고 이들과 build를 묶은 check. 게시용 빌드 `build:artifact`도 v1처럼 만든다.
7. `/_catalog` 화면: 토큰과 기본 부품(버튼, 상태 배지, 지표 카드, 금액 카드, AI 결과 카드, 그리드, 차트)을 한 페이지에 모은다.

## 완료 기준

- `npm run check`가 통과한다.
- `/_catalog`에서 테마와 밀도를 바꾸면 모든 부품이 함께 바뀐다.
- 메뉴의 모든 화면이 열리고(이번 버전 화면은 빈 템플릿, 다음 버전 화면은 "준비 중"), 역할을 바꾸면 메뉴가 바뀐다.
- `src` 아래에 색상값과 px 직접 사용이 없다.

끝나면 멈추고, 설치한 패키지와 라이선스, v1에서 가져온 것과 고친 것, 확인한 것과 확인하지 못한 것을 보고해 줘.
