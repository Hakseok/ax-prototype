# 1단계 — 설계 문서

코드를 쓰기 전에 설계 문서를 만든다. 00-진행-순서.md와 v1(`D:\ems-prototype`)의 CLAUDE.md, docs/screen-pattern-guide.md, docs/decisions.md, docs/reports/07-전체-점검.md를 읽고, v1에서 잘 된 것은 이어받고 7단계 점검에서 나온 문제는 설계 단계에서 막는다.

## 할 일

1. `CLAUDE.md` — 프로젝트 목적, 기술 구성, 라이선스, 구조 규칙, 데이터 규칙, 작업 방식. v1 형식을 따르되 이번 범위에 맞게 고친다.
2. `docs/screen-guide.md` — 화면 가이드
   - 공통 틀(상단 바, 메뉴, 제목 줄, 조건, 툴바, 본문)과 치수
   - 화면 패턴: v1의 8종을 검토해 그대로 쓸 것, 고칠 것, 새로 필요한 것(예: 경영 보고형, 원인 분석형, 대화형)을 정한다.
   - 공통 규칙: v1 가이드 6장을 출발점으로 하고, v1 보고서의 변경 제안 G-1~G-9를 반영한다(비교 기간 정의, 미수신 표시, 숫자 형식, 전사값 표기, 보조 버튼 명칭 등).
   - 금액 표시 규칙: 단위(원, 만 원, 백만 원, 억 원)와 자릿수, 확정·추정·잠재 구분 표기, "시연용" 표시 위치
   - AI 결과 표시 규칙: 근거, 신뢰도·구간, 모델·버전, 채택·기각, "가상 엔진" 표시
3. `config/menu.json` — 역할 중심 메뉴. 경영진, 공장 운영, 품질, 설비·정비, 에너지·탄소, 설정·관리 묶음으로 나누고, 각 화면에 ID, 이름, 패턴, 사업장 범위, 대상 역할, 구현 단계(이번 버전 / 다음 버전)를 적는다. 화면 ID 체계도 새로 정한다.
4. `config/company.json` — 가상 회사
   - 자동차 부품 회사 1곳, 사업장 3~4곳. 사업장마다 주력 공정을 다르게 한다(예: 프레스·용접, 사출·도장, 정밀 가공, 모듈 조립). 국내 지명만 쓰고 실제 회사와 겹치지 않는 이름을 쓴다.
   - 라인, 공정, 설비, 제품(품번), 고객사(가상 완성차 2~3곳), 교대 근무
   - 고정 "현재" 시각, 데이터 기간
   - 시연 시나리오 6~8개: 설비 이상 징후 → 정비로 정지 예방, 특정 금형·조건에서 불량 급증과 원인, 라인 성능 손실(소정지·속도 저하), 압축공기 누설 같은 에너지 낭비, 고객 클레임과 로트 추적, AX 적용 전후 개선 등
5. `config/industry-templates.json` — 업종 템플릿. 자동차 부품(기본), 식품·음료, 금속 가공 3종. 템플릿마다 권장 지표 세트, 손실 분류, 품질 지표, 원가 항목, 기본 단가 항목을 둔다.
6. `docs/kpi-dictionary.md` — 지표 사전. 지표마다 정의, 계산식, 단위, 집계 방법(사업장·전사 합산 방식: 합인지 가중 평균인지), 비교 기간, 데이터 출처를 적는다. OEE(가용성 × 성능 × 품질)와 6대 손실, 직행률(FPY), PPM, MTBF·MTTR, 계획 대비 생산, 원단위, 품질 비용 등.
7. `docs/data-model.md` — 데이터 모델. 회사 → 사업장 → 라인 → 공정 → 설비 → 센서 계층(ISA-95 참고)에 생산 실적(교대·로트), 비가동 사건, 품질 검사·불량, 공정 조건, 설비 센서·건전성, 정비 오더, 에너지, 단가를 붙인다. 파일 단위와 용량 목표를 정한다.
8. `docs/roi-method.md` — AX 효과 산정 방법. 기준선 기간, 효과 분류(확정·추정·잠재), 항목별 계산식(불량 감소, 비가동 감소, 에너지 절감, 재고·인력 등), 중복 계산 방지, 보수적 가정. 금액은 모두 가상 단가로 계산한다.
9. `docs/ai-engine.md` — 가상 AI 엔진 규격. 기능별 입력·출력 형식(이상 탐지, 잔여수명 예측, 불량 원인 후보, 최적 조건 추천, 자연어 질의 응답), 신뢰도 표현, 판정 회신, 엔진을 실제로 바꿀 때 교체할 경계
10. `docs/decisions.md` — 위 문서를 쓰며 정한 사항과 이유
11. `docs/demo-story.md` — 경영진 시연 흐름 초안(10분 안팎). 어떤 화면을 어떤 순서로 열고 무엇을 보여 줄지. 이번 버전에서 만들 화면은 이 흐름에 필요한 것을 우선한다.

## 제약

- 이 단계에서는 코드를 쓰지 않는다.
- 외부 사례 수치는 쓰지 않는다. 필요하면 "출처 확인 필요"로 표시하고 보고에 목록으로 남긴다.
- 기술 구성은 v1과 같다(Vite, React, TypeScript, Ant Design, ECharts, AG Grid Community, React Router 해시 라우팅). 추가할 패키지가 있으면 이유와 라이선스를 문서에 적는다. PDF 보고서 생성 방법(라이브러리와 한글 글꼴 처리)을 정한다.

## 보고

- 만든 문서 목록과 각 문서의 핵심 결정
- 메뉴 전체와 이번 버전에서 만들 화면 목록(화면 수, 패턴)
- 시나리오 목록과 각 시나리오가 드러날 화면
