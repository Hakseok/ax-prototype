# 3단계 — 가상 데이터

`config/company.json`, `docs/data-model.md`, `docs/kpi-dictionary.md`를 기준으로 가상 데이터 생성 스크립트와 집계 함수를 만든다.

## 할 일

1. `scripts/gen-data`를 만들고 `npm run gen:data`로 실행한다. 고정 시드로 항상 같은 결과를 낸다.
2. `public/mock/`에 아래 데이터를 만든다. 기간과 단위는 데이터 모델 문서를 따른다.
   - 기준정보: 사업장, 라인, 공정, 설비, 센서, 금형, 제품(품번), 고객사, 교대, 사용자·역할, 단가
   - 생산: 교대·로트별 계획·실적 수량, 사이클 타임, 양품·불량 수량
   - 비가동 사건: 시작·종료, 설비, 손실 분류(6대 손실), 원인 코드
   - 품질: 검사 결과, 불량 유형, 공정 조건(공정별로 다르게: 프레스 톤수·SPM, 사출 온도·압력·사이클, 가공 주축 부하·공구 수명, 조립 체결 토크), 고객 클레임과 로트 연결
   - 설비 센서: 진동, 온도, 전류 등. 건전성 계산에 필요한 만큼만 둔다.
   - 정비: 예방·사후·예지 정비 오더와 결과, 부품·인력 비용
   - 에너지: 사업장·라인별 전력, 압축공기, LNG(도장 건조 등). v1 방식(1시간 값, 최근 구간 15분 값)을 참고한다.
   - AX 적용 이력: 기준선 기간과 적용 이후 기간이 구분되도록 개선 효과가 데이터에 드러나게 한다.
3. 시나리오 6~8개가 데이터에 실제로 드러나게 한다.
4. `src/data`에 로더와 집계 함수를 만든다. 사업장(개별·전사), 라인, 기간, 제품, 교대로 집계할 수 있어야 한다.
5. 단위 테스트: 라인 합 = 사업장 합 = 전사 합, 양품 + 불량 = 생산, 비가동 시간과 가동 시간의 합 = 계획 시간, 로트 추적(클레임 → 로트 → 설비·조건)이 끊기지 않는지.

## 제약

- 실제 회사·제품·설비 이름과 번호를 쓰지 않는다.
- `public/mock` 용량이 설계 문서의 목표를 넘으면 줄일 방법을 제안하고 멈춘다. 게시 제한(파일 수·용량)도 고려한다.
- 단가는 모두 가상이며 데이터 파일에 `demoOnly: true`를 둔다.

## 완료 기준

- `npm run gen:data`를 두 번 돌려 결과가 같다.
- 테스트가 통과한다.
- 시나리오마다 어느 파일의 어떤 값에서 확인되는지 표로 보고한다.

끝나면 멈추고 보고해 줘.
