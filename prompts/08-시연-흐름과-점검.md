# 8단계 — 시연 흐름 확정과 전체 점검

구현을 고치기 전에 먼저 점검만 해서 보고한다. 수정은 보고를 본 뒤에 따로 요청한다.

## 할 일

1. `docs/demo-story.md`를 실제 화면 기준으로 확정한다. 화면 순서, 누를 곳, 보여 줄 수치, 말할 내용, 예상 질문과 답(특히 "이 금액의 근거는?", "AI가 틀리면?", "우리 회사 데이터로는 얼마나 걸리나?")
2. 시연 흐름대로 처음부터 끝까지 직접 진행하며 막히는 곳, 수치가 어긋나는 곳, 설명이 필요한 곳을 찾는다.
3. 이번 버전 화면 전체를 1920×1080, 밝은·어두운 테마에서 열어 겹침, 잘림, 빈 영역, 콘솔 오류를 확인한다.
4. 수치 대조: 경영 현황 ↔ 분석 화면 ↔ AX 성과 ↔ PDF, 전사 ↔ 사업장 합산, 정비·품질 조치 후 효과 반영
5. 역할별 사용자(대표이사, 공장장, 품질, 설비, 관리자)로 메뉴·버튼·사업장 범위 확인
6. 가이드 공통 규칙 위반, 설계 문서에 없어 임의로 정한 것 전부
7. `npm run build:artifact`로 게시용 빌드를 만들고, 게시 전 확인 사항(파일 수, 용량, 해시 주소, PDF 저장)을 보고한다. 게시는 승인을 받은 뒤 한다.

## 보고 형식

- 화면 ID별 결과 표: 확인함 / 문제 있음 / 확인 못 함
- 문제 목록: 화면 ID, 증상, 어긋난 규칙, 제안하는 수정, 심각도
- 시연 흐름 점검 결과와 예상 질문 답변 초안
- 다음 버전에 넣을 기능 제안

`docs/reports/08-전체-점검.md`로 남기고 멈춘다.
